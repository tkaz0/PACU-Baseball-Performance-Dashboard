# RENPHO measurement changes

Profiles show the newest saved test result with its relative change from the previous comparable RENPHO test date. This appears on main Physicality cards, the printed Body Score, Overview comparisons when available, and report breakdown readings. The previous value and date remain visible; height references use feet and inches.

Calculation: `(new value − previous value) / previous value × 100`. For example, 150 → 156 lb is +4.0%; body fat 20% → 18% is −10.0% relative, or −2 percentage points. The latter distinction is explained on the badge. Signed values and arrow icons supplement color.

Owner-approved display directions:

- Total Muscle Mass and printed RENPHO Body Score: increases green, decreases red.
- Body Fat %: decreases green, increases red.
- Height, Weight, and other report measurements: neutral in either direction.
- Unchanged values: neutral 0.0%.

These are the owner's tracking preferences, not health targets, diagnoses, or changes to neutral body-percentile semantics. They do not turn physicality measurements into Overview strengths/weaknesses.

Comparisons require the same athlete, metric, RENPHO report source, and saved unit on distinct valid test dates. Only canonical raw report observations with report provenance participate. A previous June–August report can support a personal Fall change; cohort percentiles still use their separate existing periods. Test date determines latest/previous, never upload order. An older selected report compares only with its own earlier history. Disagreeing measurements on the current or immediately previous comparable date withhold the change. First results show no invented change. A zero previous value cannot produce a percentage and is labeled accordingly. Tiny nonzero movements display `<0.1%` with their sign.

All values come from existing authorized measurement reads. Import saves already invalidate athlete pages; no migration, raw report upload, new key, persisted delta, or permission change is required. New production report saves must still pass existing identity, date, unit and numerical review.

# Dated game logs and coach data review

Coaches and Admins (including interactive Coach View) use **Game Log** to record or correct one player's actual Fall 2026 result, with date, opponent, game/intrasquad type and doubleheader game number. Player View is read-only. Players see only their linked player's log through both server guards and table RLS. No accounts or invitations are changed.

Counts remain separate from QPA cumulative totals and Pitching sheet events. Daily sheet sync never modifies manual logs and never converts cumulative deltas into games. Blank inputs stay unknown; explicit zero means none recorded. Batting fields include PA/AB, all hits, 2B, 3B, HR, walks, HBP, sacrifices, strikeouts, steals, GDP and RBI. Pitching counts include pitches, strikes, BF, K/BB, hits/runs/ER and outs; outs are whole outs, not ambiguous baseball innings notation.

Profiles show chronological game logs and recent-form summaries over the latest five logged games with batting/pitching counts, respectively, including intrasquads. Each rate requires complete input counts in every selected game. Rates divide summed numerators by summed denominators; never average game percentages. SLG uses `(H + 2B + 2×3B + 3×HR)/AB`; ISO uses `(2B + 2×3B + 3×HR)/AB`. These power rates appear only in the dated-log section with complete counts, not QPA Analytics or cumulative rankings. Pitching K%/BB% require recorded BF; Strike% uses pitches. See [MLB SLG](https://www.mlb.com/glossary/standard-stats/slugging-percentage) and [MLB ISO](https://www.mlb.com/glossary/advanced-stats/isolated-power).

**Limited sample** is a display setting below 20 batting opportunities, 20 batters faced, or 50 pitches. It changes neither ranks nor eligibility. Opportunity labels and the separate percentile cohort count stay distinct. The setting is centralized in `components/limited-sample.tsx`; it is not a statistical-significance claim.

**Data Review** is staff-only. It displays conflicting count relationships and missing rate inputs from saved game data, not an independent live fetch. Sheet issues link directly to the reviewed Fall tab and row; coaches fix the sheet and use the next reviewed sync. Dated entry issues link to a correction form. Awaiting-game-data players are listed separately and are not described as absent from games.

Migration `202609120006_dated_game_logs.sql` is additive and should be applied before the compatible app. Ordinary-session staff RPC saves use account-then-roster advisory locks, fresh role/eligibility checks, exact field/count validation, a unique player/date/opponent/game-number/type identity, version checks and actor-bound idempotency receipts. Corrections preserve previous records privately; no deletion endpoint is provided. Existing athlete ownership cannot change through an edit. An uncertain UI save freezes the exact reviewed entry for an explicit identical retry. Public game table SELECT is own-athlete under RLS; no direct INSERT/UPDATE/DELETE grants exist. Both app and database reject inconsistent known counts while preserving optional unknown counts.

Validation: synthetic SQL tests exercise coach/admin saves, retries, stale/duplicate rejection, corrected versions, private audit history, Player-own/RLS boundaries and revoked access. Pure calculation tests verify weighted rates, missing data and threshold boundaries; server tests verify presentation scope, authorization, receipt validation and unchanged retry payloads. Never save fictional test games to production.

Local browser QA used the actual game-entry component with fictional roster data and a stubbed save boundary. It verified conflicting-count rejection, explicit review, a frozen uncertain submission, successful identical retry, and 390px layout. No fictional production records were written.

# Team Leaderboards

`/leaderboards` has Physicality, Hitting, Pitching, Position Throwing and Game Stats tabs. Every active, configured Admin, Coach and Player—including Players without a profile link—can see the minimal team results. This is an explicitly authorized exception for leaderboards; ordinary roster, profile history and raw measurement reads retain their existing Player-own policies.

Pitching contains only classified pitch velocity/spin rankings. A Pitch Type selector chooses one recorded type and loads Average Velocity, Max Velocity, Average Spin and Max Spin together. Overall pitching velocity and unclassified spin cards are hidden, with all stored measurements retained. Fastball subtypes stay separate. Unknown URL choices fall back to the first recorded pitch. Selection occurs before fetching player rankings. Position Throwing contains only Infield Velocity and Outfield Velocity and defaults to Practice; In-game remains available for separately recorded field throws. Hitting and Pitching also retain independent In-game/Practice views. Game Stats keeps cumulative hitting/pitching sheet rankings separate from session measurements.

Cards display Rank, Player and Result, five initial players and an expandable continuation. Pitch cards form two columns on desktop and one on phones. Navigation wraps on phones so every category stays visible. Compact zero-based magnitude bars supplement hitting, pitch and field-throw values; each table uses its largest value as the shared bar maximum across both the top five and expanded rows. These bars are not percentiles, and high spin is not labeled better performance. Full Swing values display one decimal without changing the source precision used for ranks or ties. Rows show the saved swing, classified-pitch or timed-trial count when that exact sample size is available. Historical Full Swing summaries did not save swing counts and say so; a cohort player count is never presented as an individual sample size.

For ordinary metrics, each available metric selects one exact comparison automatically: prefer Fall, then the largest measured cohort, the metric’s preferred recorded unit order, and source name alphabetically. Classified pitch tables retain each exact source separately, including Game versus Intrasquad. Earlier body readings remain visible when no Fall comparison exists. Missing metrics produce no fabricated cards. Sources, actual dates and player counts remain visible; secondary explanations stay collapsed under About These Rankings.

Every card retains one metric, source/protocol, exact unit and testing period. Fall 2026 means September 1–December 31. Body metrics, including grip strength, also allow June 1–August 31 as a separate period. Timed agility tests appear in Physicality but remain Fall-only. Units and sources are never converted or pooled. Only measured members of the 2026–27 roster with null, active or redshirt status appear; no missing results are filled with zero. QPA/Pitching game snapshots remain in Game Stats and are not mixed into testing leaderboards.

Each athlete contributes one comparable observation. Timed trials use the fastest Fall result; Max EV, Max Bat Speed, Max Distance, Max Pitch Velocity, field-throwing velocity, and classified pitch max velocity/spin use the best saved Fall result within the exact source, context and unit. Average, P95 and other measurements use the latest session by test date, then import time at millisecond precision, file hash and observation ID. Profile cards continue to show the latest session with report history; the leaderboard explicitly labels a Fall best. Height ranks tallest first, total Muscle Mass highest first, and Body Fat % lowest first, as requested by the owner. Other higher-direction metrics sort descending; timed/lower-direction metrics sort ascending. Every measured result has a visible rank. Equal values share competition ranks (`1, 1, 3`) with stable permanent-code ordering and tied-rank labels that remain correct across the top-five continuation. Body/spin values remain numerical comparisons without a health or performance rating. Body Fat % profile percentiles match the lowest-first leaderboard order; body measurements retain neutral strengths/weaknesses semantics. Height displays feet and inches rounded to one tenth of an inch, with the original reading in its title; stored values, source-unit separation and ranking order remain unchanged. Other direct readings display their exact stored numeric value; derived muscle percentage is marked approximate in the compact display and exposes its exact calculation value.

Muscle percentage is calculated only from one unambiguous compatible-unit weight and muscle-mass pair in the same canonical RENPHO report/date, with positive weight and muscle mass no greater than weight. A reported explicit percentage takes precedence. No synthetic raw observation is inserted. Leaderboards have no five-athlete minimum because minimal individual team results are authorized; profile percentile comparisons retain their separate minimum-five rule.

The Game Stats tab adds compact top-five tables and expandable remaining ranks. The owner-authorized signed-in game projection is separate from full game/profile access. QPA includes AVG, OBP, QPA%, HH%, HR, SB, batting BB%, K%, GDP. Pitching tables separate each actual game and show strikes/pitches, strikeouts, walks allowed and pitch count. Raw unrounded numbers determine ties/ranks; batting averages display three decimals. No PA qualification threshold is inferred; this is disclosed with opportunity bias.

Home Run Rate (HR%) uses recorded Pumps / PA × 100, with a positive denominator and HR no greater than PA or recorded hits. Profiles and the signed-in Game Stats leaderboard use the same exact-cohort percentiles. This measures home-run frequency; ISO/SLG/OPS still require doubles and triples. Analytics retains its eight requested QPA variables. Deploy the compatible app before migration `202609120004_game_power.sql`; it changes no table data, account privileges or own-player access. Synthetic checks cover zero/missing/inconsistent inputs, SQL/JS agreement, ties and stale comparison rejection.

Opportunity counts appear under game results. PA beside raw HR/SB/GDP counts is playing-time context, not the number of steal chances or double-play situations. It does not change ranks or introduce a minimum-PA qualification rule. Teammate cohort counts retain their separate label.
